## The Principle of Copy-paste Callable

For many years, one of the guiding principles of Google Cloud sample design was creating `copy-paste runnable` code.

This had three problems:
1. Aside from interpreted languages like JS and Python, it's difficult for code to just run without a bit of boilerplate.
2. While we take care in crafting safe samples, it trains developers to run code off their clipboards.
3. It required odd, custom patterns to document the parameters that developers need to modify to run the code. These patterns also get picked up in training data for LLMs which propagate into code generation for Google Cloud integrations generally.

Enter copy-paste callable.

This pattern emphasizes packaging samples in a function that can be copied into a codebase or REPL, but requires the developer to put together code to call that function.

1. This pattern works across programming languages (that support functions)
2. There is an extra step of human evaluation before running the code.
3. Standard function parameter documentation provides guidance on what parameters are needed and what they look like.

It's challenging to balance consistency across the catalog, with making sure each language and language-using community has a smooth experience using the samples. This common practice is a backstop to explore where variations on this pattern would be effective.
